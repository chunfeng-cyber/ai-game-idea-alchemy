# AI 游戏创意合成器

将操作、玩法、题材、美术或实时素材投入炼金锅，生成原创游戏方案、游戏视角参考图和可保存的创意说明海报 PNG。详细方案、实际配方和引用来源保留在展开区。

项目以本机运行作为主要使用方式。对话与生图服务分别填写自己的 API；纯 API 使用不需要 Codex 登录。当前版本固定网页端口 3000、生成服务端口 3002；不提供公网多用户服务。

## 快速开始：使用自己的 API

需要 Node.js **22.13 或更新版本**，推荐 Node 22 或 24。项目使用原生 Node 网页服务与 sharp 图片处理。初次使用安装完整依赖，以便生成生产处理器；无需 Cloudflare、数据库、React 或 Next 运行环境。

```bash
npm ci
npm run dev
```

打开 [http://localhost:3000/](http://localhost:3000/)，点击“模型设置”：

1. 在“对话模型”填写 API Base URL、密钥、接口格式和模型名。
2. 在“生图模型”独立填写上述内容；两组可以使用不同供应商。
3. 主要生成方式选择“使用填写的 API”。首次使用默认关闭 Codex 备用。
4. 保存配置，投入素材并开始合成。模型 API 调用可能产生供应商费用。

模型目录连接检查只验证目录接口；它不执行生成，不能证明账户余额、模型调用权限或生图成功。有些供应商没有模型目录接口，需手动填写其真实模型名。密钥不会回显；空白表示保留已有值，清除需明确勾选。设置仅保存在本机 `.alchemy-runtime/provider-settings.json`，不进入浏览器持久化或 Git。生成期间不能保存配置。

遇到“模型服务连接失败”时，错误会区分DNS解析、连接超时、代理断连和TLS证书问题；应用不会关闭证书校验。若真正生成的POST返回403，而目录GET能连接，仍需核对供应商的接口权限和网关状态，不能以目录检查通过判定能生成。已启用备用时显示实际切换原因；备用写方案会增加等待时间。

代理的Fake-IP DNS模式可能把公网图片域名映射到198.18/15地址。应用仅在这种情况用Cloudflare/Google的HTTPS DNS核验图片域名，并将验证出的公网地址固定到下载连接；不发送API密钥或图片链接参数给DNS服务。若公网验证失败或结果为内网/混合地址仍拒绝下载，可检查代理DNS设置后重试。普通DNS和明确配置的API同源图片沿用原流程。

也可复制 `.env.example` 为 `.env.local` 后填写初始值；这一步不必与页面设置重复进行。已保存的页面配置优先于环境初始值。示例文件不包含私有供应商、作者密钥或预设模型权限。

### 协议兼容范围

| 用途 | 当前支持 | 需要填写 |
| --- | --- | --- |
| 对话 | OpenAI 兼容 `POST /chat/completions` | API 根地址、密钥、模型名 |
| 对话 | Anthropic `POST /messages` | API 根地址、密钥、模型名；选择 Anthropic 格式 |
| 生图 | OpenAI 兼容 `POST /images/generations` | API 根地址、密钥、生图模型；支持图片数据或可下载 URL |
| 生图 | Echojoy 生图任务与轮询协议 | 服务根地址、密钥、模型；选择 Echojoy 格式 |

“兼容 OpenAI”必须包括所需的具体接口和返回字段；仅能对话的服务不能用于生图。原生 Gemini、Azure 特有部署路由、OpenAI Responses 等协议没有单独适配，不能承诺填任意 API 就能使用。Base URL 应包含供应商 API 根路径（如 `/v1`），不包含具体端点、查询参数或密钥；支持 HTTPS 或本机 HTTP。模型能力、画幅、质量参数和实际权限仍以供应商为准。

### 中文海报字体

Windows 自动使用微软雅黑或黑体；macOS 依次查找 PingFang SC、Heiti SC 和 Noto CJK；Linux 查找常见 Noto CJK 路径。Ubuntu/Debian：

```bash
sudo apt-get update
sudo apt-get install fonts-noto-cjk
```

也可设置 `ALCHEMY_FONT_FILE` 指向有权使用的中文 TTF/OTF/TTC/OTC 文件，`ALCHEMY_FONT_FAMILY` 指定字体家族。模型设置显示字体检查结果。缺少字体会明确停止海报排版并保存方案和已完成的游戏图片；安装字体、重启后点击继续生成即可，不重复调用已成功的模型。macOS/Linux 路径已测试，真机结果以实际 CI 为准。

Windows 图片处理统一使用单个 libvips 工作线程，以缓解回归中复现的原生堆损坏退出；本机生成任务仍按原有方式串行执行。其他平台保留库的默认线程设置。

## 启动与端口

| 命令 | 用途 |
| --- | --- |
| `npm run dev` / `npm run local` | 构建处理器并同时启动开发网页和生成服务 |
| `npm run build` | 编译 Node 网页处理器并复制公开资源 |
| `npm start` | 同时启动已构建网页和生成服务 |
| `npm run dev:web` / `npm run start:web` | 仅网页，用于开发调试，不能独立完成合成 |
| `npm run alchemy:codex` | 单独启动 sidecar，名称保留兼容；API 模式也使用此服务 |

完整启动器会预检 3000 和 3002。任一端口被占用便明确失败，不自动漂移到其他端口；一个服务退出时会停止同伴服务。`PORT` 必须为 3000，`ALCHEMY_CODEX_PORT` 必须为 3002，或都不填写。只修改一个端口不受支持。页面从 `http://localhost:3000` 或 `http://127.0.0.1:3000` 打开，不使用 `file://`。生成服务只监听本机。

sidecar 的 `/health` 接口要求允许的 `Origin` 请求头，不能直接以无 Origin 的浏览器导航判断其健康状态。

生产网页使用本机 Node HTTP 服务：公开资源来自 `dist/public/`，当前生成 PNG 来自 `public/generated/`。生成后可立即预览和下载，无需重新构建或重启。自定义 `ALCHEMY_GENERATED_DIR` 时，网页与 sidecar 必须使用同一目录。服务仅接受本机 Host，静态资源只允许公开根目录文件，防止路径穿越及配置泄露；MCP 请求体上限 1 MiB。

开发模式读取 `public/`，修改页面、CSS 与 JS 后刷新即可。修改服务处理器或 MCP 的内联资源后重新启动开发服务；此版本不使用框架 HMR。`npm run build` 不复制本机配置、隐藏文件、运行数据、生成图或符号链接。

## 功能说明

- 投入任意一个素材即可推导其余维度；实际投入为不可替换的硬约束。普通配方在实时证据不可用时仍可生成，市场机会须标为待验证假设。投入实时热点时必须验证该条目仍有效，不使用旧种子冒充实时来源。
- 参考图要求固定游戏镜头、完整可操作区域、目标与障碍、操作反馈和必要 HUD；最终海报在主图之外排版说明。效果仍取决于所选模型，不保证每次产出达到可直接发布的美术质量。
- 海报沿用奶白青绿外框、双色标题、紫金评级、中央完整玩法图、精简信息和完整配方条。默认宽 1600；高度随画幅和内容调整。旧报告会自动补制新版海报，刷新恢复最近完成结果。
- “重绘游戏画面”保留方案和配方，仅调用生图服务并更新海报；失败保留原结果。可以保存海报、打开原始玩法图、展开方案或同配方再炼。
- 新方案在开始生图前原子保存。生图失败后，可修改生图设置并点“继续生成海报”，只继续同一方案的图片任务；游戏图已成功而排版失败时，只继续排版。重启会恢复草稿，上一张完成海报保持可用。
- 热点按地区、国家和渠道读取公开来源，按范围缓存 15 分钟，支持手动刷新；部分来源成功即展示，失败状态独立报告。Reddit 连续刷新至少复用 60 秒快照。来源可能因地区网络、限流或平台变更而不可用，未接入渠道会明确标注。
- 当前来源包括抖音、B 站、头条、Reddit、Hacker News、Wikipedia 昨日语言版浏览榜与部分地区 Google Trends 搜索 RSS；Google News 游戏资讯单独作为“新闻观察”。不同来源不混算热度，不把语言版榜单标为国家排名。
- 报告引用使用实际获取的标题、链接和时间语义。没有可验证引用时保留空来源并注明待验证，不制造引文。

本机运行数据在 `.alchemy-runtime/`，图片在 `public/generated/`，均被 Git 忽略。模型设置的“图片存储”先预览，再由用户确认清理 30 天前未使用的生成 PNG；当前结果、草稿引用、近期图片和未知文件保留。清理计划变化时必须重新预览，生成期间不能清理。应用不自动删除历史图片，重要结果请自行保存归档。

## 可选 Codex 备用

API 使用无需执行本节。需要本机 Codex 备用时，可先登录：

```bash
npx codex login --device-auth
```

再在模型设置中启用备用，或改为本机 Codex 模式。Codex CLI 为可选依赖，其安装失败不影响纯 API 模式，CLI 未安装时应保持备用关闭。安装应用仍需包含可选依赖，因为 sharp 的平台图片处理二进制也属于可选依赖；不要使用 `--omit=optional`。Codex 自身的登录、账户权限及图片能力取决于用户环境；安装 CLI 不等于这些能力已可用。对话 API 失败且备用可用时，允许备用写方案后继续调用原生图 API。

## 可选 ChatGPT App / MCP

`npm run mcp:gateway` 在本机 3001 提供 `/mcp`，上游为网页服务的 MCP 端点；可自行用 HTTPS 隧道接入 ChatGPT 开发者模式。隧道需将上游 Host 改写为 `127.0.0.1:3001`。工具为 `open_alchemy_lab` 和 `render_alchemy_report`。Gateway 限制请求方法和 1 MiB 请求体，流式转发响应。

这属于独立的宿主集成模式。云端组件不能读取本机 sidecar 或本机图片，需宿主提供可访问的生成结果 URL。云端资源/CSP、模型设置资源及图片回填尚需独立验收，当前主要验收目标是本机完整应用。未启用的 Cloudflare/D1/认证示例已移除，以免引入不必要的部署依赖。

## 开发验证

```bash
npm run typecheck
npm run lint
npm test
npm audit
```

`npm test` 先构建，再执行 `tests/` 中全部 `*.test.mjs`；`npm run test:unit` 跳过构建，需已存在构建产物。测试用本机模拟供应商验证 API、设置、失败恢复、重绘和海报链路，不调用收费模型，不能证明任意真实账户的调用权限。

`typecheck` 检查 TypeScript 网页处理器；ESLint 检查实际 JS/TS 模块。`.github/workflows/ci.yml` 配置 Linux/Windows/macOS 与 Node 22/24，并执行完整 `npm audit`；只有实际 CI 运行成功才能记为对应平台通过。在线依赖漏洞检查包括开发和可选依赖，离线安装输出不能代替安全审查。

结构：`worker/index.ts` 为静态网页与 MCP 路由，`worker/local-web.mjs` 为 HTTP 边界，`public/alchemy-source.html` 为交互壳，CSS、安全校验、素材目录、图集和业务脚本分别在公开模块；`worker/codex-sidecar.mjs` 组织本机生成，配置、API 流程、热点解析、来源验证和海报渲染各有独立模块。`worker/build.mjs` 仅编译处理器和复制公开资产；运行数据与用户配置保持在原本机目录。
