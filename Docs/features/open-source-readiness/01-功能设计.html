方案草稿与继续生图 · 2026-10-07

现状取证：worker/provider-flow.mjs 在新方案完成后生图失败会丢失方案；已有重绘接口仅针对 latestResult，重新合成会重复对话请求及费用。提案：对已校验的新方案立即单独原子保存为本机草稿；图片成功后保存其路径，再排海报。失败时旧完成海报保持，草稿可跨重启继续；备用生图也使用同一方案，不重做文本。

接口：GET /api/draft 返回 view:draft 或 empty；POST /api/resume-image 校验 draftId 与 sourceDraftVersion，继续当前草稿的图片/海报阶段。健康与失败响应提供草稿就绪状态。恢复不刷新热点、不再次调用对话模型；历史证据保持生成方案时的来源时间，前端仍可查看。草稿包含方案、配方、来源与任务元数据，不含供应商密钥。

职责：generation-draft.mjs 管理原子存储、校验和阶段更新；provider-flow.mjs 在方案完成时回调保存并提供只生图备用；codex-sidecar.mjs 负责互斥、供应商调用、PNG及海报完成；前端增加明确继续入口，旧报告重绘保持原含义。

验收：模拟生图失败后重启再继续，chat请求计数不增长；错误/过期恢复ID返回409；再次失败保留草稿及旧海报；成功替换结果并清草稿；图片已成但海报失败后恢复不重复生图；不产生付费外部模型调用。

本轮已落地的恢复与安全边界 · 2026-10-07

实现：generation-draft.mjs 原子保存新方案与阶段；image-task.mjs 统一已有方案的生图与备用状态；provider-http.mjs 管理鉴权、响应体与错误；image-download.mjs 在TLS socket解析阶段固定已校验公网DNS答案，逐次校验重定向，精确自托管API origin可下载自身图片；local-http.mjs 限定JSON对象、100KB与10秒收包。输入图片限制30MB与4000万像素，归一化后的补边画布限制最大边4096与1600万像素；保持完整HUD，不裁边。主API不自动重定向，图片下载不附加模型密钥头。模型报告仅选已知字段；配方1500、名称128、标语512、说明6000、提示词20000、图标24字符，来源最多6条，过长在任何生图前拒绝。所有图片文件由服务器UUID命名；当前完成或草稿请求ID重用返回409，历史ID复用也不能覆盖旧图。generation-results.mjs以原子发布和异步快照比较保护慢海报迁移。

本机维护为手动预览后清理：GET /api/maintenance 返回候选旧图片计数、字节和planToken；POST /api/maintenance/cleanup 校验预览Token，仅删除30天以前可信生成PNG，保留当前结果、草稿和未知文件，生成活动期间409。字体health状态不暴露本机路径；缺中文字体时保存游戏图，修复后继续排版不再次生图。

已实测：生图403保留新方案与旧海报，重启后继续成功且文本请求数不增长；中文字体缺失后仅恢复排版，文本和图片请求数都不增长。维护真实HTTP预览、过期token与生成互斥通过；HTTP/SSRF/输入与状态任务定向检查全部通过。补充：3项异步结果发布交错测试确认内存、磁盘及重启后的新报告不会被旧海报迁移覆盖；历史请求ID复用后排版失败，原游戏图及海报SHA256保持；大报告拒绝时image请求数不增长；实际小长条图片按1:3补边完整归一化成功。全项目最终回归由04验收记录汇总。
