依赖与本机服务迁移

open-source-readiness · 2026-10-07 · 已确认范围内实施设计

目标与现状取证

用户要求“继续处理 把高危等所有的问题都解决”。18项依赖问题中17项来自无业务需求的框架、Cloudflare、数据库及Next lint链；图片处理sharp为剩余直接风险。当前app/page.tsx只嵌入public/alchemy-source.html，业务运行在Node sidecar。没有启用D1或ChatGPT认证。

提案：将网页壳改为原生Node HTTP服务与Web Request处理器，删除未使用链，升级sharp补丁；不通过忽略dev依赖、审计白名单或关闭安全检查降低计数。

范围与用户体验

保留桌面720×405炼金器、/与/alchemy、网页静态资源、实时生成PNG、独立模型API、Codex备用、/mcp两工具、自包含组件和已停用API的410结果。移动屏幕外壳适配视口，由现有组件处理内部布局。公网多用户与Cloudflare部署不属于本机应用范围，删除未启用示例不移除已使用能力。

无新增交互分支，进入/关闭/选中/结果恢复继续使用现有组件。开发编辑公开HTML/CSS/JS后刷新即可；不再依赖框架HMR。

技术切片

worker/index.ts负责网页壳、公开资源和MCP路由；worker/local-web.mjs负责本机绑定、原始请求路径与Host检查、有限请求体和流式响应；generated-files保留实时PNG安全边界。build使用TypeScript编译少量处理器并复制公开静态文件；ESLint检查实际JS/TS服务，去掉React/Next规则。runLocalApp继续管理两个子服务。

验收与风险

  • 全依赖在线npm audit为0，包含dev与optional；重新生成锁并真实安装。
  • 构建、TypeScript、ESLint及全部既有测试通过。
  • HTTP测试覆盖路径编码、反斜线、symlink、秘密文件、错误Host、方法、请求上限、实时图片及MCP。
  • 实际浏览器保持原报告、桌面视觉、设置与图片保存，无收费调用。

sharp升级涉及原生库，必须实际验收中文海报与字节输出。代码许可证与既有图片授权由其他切片处理，不能以移除构建链替代许可。
